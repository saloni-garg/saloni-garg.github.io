Chapter 6 · Validating Layer 3

Trust, Measured

Calibrating the LLM judge against human judgment, per capability. Chapter 5 built the judge and left every score provisional. This chapter decides, with matrices and arithmetic, which capabilities the judge may gate, which it may only warn on, and which it must never clear.

By the end, you can answer four questions

  • What does agreement mean once chance and the base rate are removed?
  • How do you sample and label so the agreement number means anything at all?
  • Which error does your gate actually pay for: the false pass or the false alarm?
  • What happens to trust the day the judge model changes?

How this lecture runs

  • 20 to 25 minutes, 22 slides: one judge, validated, trusted in pieces
  • Section 1: build the validation set, slides 4 to 6
  • Section 2: measure agreement per capability, slides 7 to 14
  • Section 3: keep it calibrated, slides 15 to 21
  • Every agreement claim shows its matrix, its formula, and its arithmetic
Input: judge verdicts from Chapter 5 + candidate outputs Output: calibration_report.json + a written trust table Status at the end: trusted per capability, or explicitly not

Slide 02 · Deliverable and recap

The judge applies for a job. Calibration is the interview.

terminal · the calibration run
$ python -m evals.calibrate \ --items datasets/judge_golden_v1.jsonl \ --labels labels/human_labels_v1.jsonl \ --judge runs/judge_v4.yaml # humans and judge scored the identical items wrote runs/2026-10-30_cal/calibration_report.json per capability: matrix, kappa, false pass rate, abstain rate, decision

The deliverable, precisely

  • A human-labeled validation set: frozen, versioned, labeled blind. Slides 4 to 6.
  • An agreement report per capability: confusion matrix, raw agreement, kappa, false pass rate, abstain rate. Slides 7 to 14.
  • A written trust decision per capability: GATE, WARN ONLY, or DO NOT USE, each with an expiry date. Slide 12.

Recap: what Chapter 5 established

  • The judge is implemented. Structured verdicts, evidence first, claim tables, per capability.
  • Its biases are measured. Position, verbosity, and self preference were run as experiments, not listed as risks.
  • Every judge score is marked provisional. The runner refuses to let an uncalibrated verdict block a release.

Provisional was not a courtesy

So far the judge has only been compared against itself: run to run variance, swap consistency, agreement with its own second sample. That measures stability, not correctness. A judge can be perfectly stable and systematically wrong. Calibration is the first comparison against an external standard: blind human labels on the identical items. Today the scores earn trust, or lose it.

Why identical items are non-negotiable

Agreement is defined item by item. Humans and the judge must see the same output, same retrieved context, same rubric text. Compare a judge score on one sample against human labels on another and you have measured sampling noise, not the judge. One item set, two independent labelings, one comparison.

Why the pipeline ends in a policy, not a score

The output of calibration is decisions: which capabilities this judge may gate, which it may only report, which stay human. Collapsing that into one trust number repeats the Chapter 2 mistake one level up, a single average hiding exactly the capability that should never have been trusted.

Engineering question answered: what evidence would let this judge block a release, and what evidence revokes that right?

SECTION 1 Build the Validation Set SLIDES 4 TO 6 · SAMPLING · LABELING PROTOCOL · THE HUMAN CEILING
Slide 04 · Sampling for calibration

Sample where the judge can be wrong

Stratify on three axes

  • Capability: faithfulness, instruction following, helpfulness, safety flagging. Sampled and reported separately, always.
  • Difficulty: the easy, medium, and hard tags already on the golden set from Chapter 3.
  • Predicted outcome: judge pass and judge fail items both, so every cell of the confusion matrix fills with real counts.

Then oversample failures and borderline cases. A random production sample is mostly easy passes: at a 95 percent pass rate, 100 random items yield about 5 fail items, and fail recall is unmeasurable on 5 items. Borderline means deterministic scores and the judge disagree, or the judge claim table splits. That is where calibration information lives.

The precision note, with the arithmetic

Agreement is a proportion, and its 95 percent band is roughly 1.96 × sqrt( p × (1 - p) / n ). At observed agreement p = 0.85:

Items per capabilitysqrt term95% band
n = 50sqrt(0.1275 / 50) = 0.0505plus or minus 9.9 pts
n = 100sqrt(0.1275 / 100) = 0.0357plus or minus 7.0 pts
n = 200sqrt(0.1275 / 200) = 0.0252plus or minus 4.9 pts

The band is per capability, not overall. Two hundred items spread across four capabilities is 50 each, and a plus or minus 10 point band cannot certify a gate. Budget items per capability first, then total them.

SLIDE 04 / 22PACE 3:10
Slide 05 · Human labeling protocol

Labels are the ground truth. Protect them like it.

The protocol

  1. Blind, both ways. The labeler sees the query, the retrieved context, and the candidate output. Never the judge verdict, and never which model or prompt produced the output.
  2. The guide is the rubric, verbatim. The labeling guide is the Chapter 5 rubric text, unchanged. If humans apply a different standard, you measure rubric drift, not judge error.
  3. Evidence with every verdict. Labelers record the evidence span behind each verdict, the same requirement the judge works under. A verdict without a span cannot be adjudicated later.
  4. Independence first. No conferring during labeling. Discussion happens only in adjudication, and the original labels are kept alongside the outcome.
one label record · human_labels_v1.jsonl
{"item_id": "faith-0231", "labeler": "L2", "verdict": "fail", "evidence_span": "refund window stated as 30 days; retrieved policy says 14 for this plan tier", "rubric_version": "rubric_v4"}

Disagreements between labelers are data

They are not errors to hide or average away. A labeler disagreement marks ambiguous rubric text or a genuinely borderline output, and it feeds two things later in this chapter: the human ceiling on slide 6, and the disagreement taxonomy on slide 10. Delete the disagreements and you delete the two most useful signals calibration produces.

Slide 06 · The human ceiling

First measure humans against humans

Before the judge is graded, grade the standard. Double-label a subset with two independent labelers and compute human versus human agreement per capability, with exactly the math the judge will face.

Human versus human agreement · example calibration

Faithfulness91% agree
Safety flagging94% agree
Instruction following88% agree
Helpfulness82% agree

Example calibration: 60 of the 200 items per capability carried two independent labels. These four numbers are the ceilings for slide 12.

What the ceiling does to the reading

A judge cannot be validated to a standard humans themselves do not meet. Read judge agreement against the ceiling, not against 100 percent. A judge agreeing with humans on 80 percent of helpfulness items sits near the 82 percent human ceiling. The same 80 percent on faithfulness, where humans agree at 91 percent, is a failing judge. Same number, opposite verdicts.

Low human agreement is a rubric bug

If two careful labelers applying the same rubric disagree on a fifth of helpfulness items, the defect is in the rubric definition, not in either labeler and not yet in the judge. Fix the definition, relabel the subset, re-measure the ceiling. Judging the judge against an undefined standard produces a precise number about nothing.

Row totals are the human standard: 78 passes, 22 fails. Column totals are the judge: 75 passes (71 + 4), 25 fails (7 + 18). Every statistic in this section is arithmetic on these four cells.

The arithmetic

overall agreement(71 + 18) / 100 = 89%. The headline, and the least informative number here.
fail recall18 / 22 = 81.8%. Of the outputs humans failed, the judge caught 81.8 percent. Four bad outputs walked through.
fail precision18 / 25 = 72.0%. Of the outputs the judge failed, 72.0 percent were real failures. The other 7 were false alarms.
pass precision71 / 75 = 94.7%. When the judge says pass, it is right 94.7 percent of the time, on this base rate.
false pass rate4 / 22 = 18.2% of human-failed items were cleared by the judge. This is the number the gate lives or dies on, slide 9.
SLIDE 07 / 22PACE 6:25
Slide 08 · Cohen kappa · same example calibration matrix

Raw agreement flatters. Kappa removes the base rate.

kappa = ( Po - Pe ) / ( 1 - Pe )
QuantityDerivation from the slide 7 matrixValue
Po, observed agreement(71 + 18) / 1000.89
Pe, chance agreement(0.78 × 0.75) + (0.22 × 0.25) = 0.585 + 0.0550.640
kappa(0.89 - 0.64) / (1 - 0.64) = 0.25 / 0.360.69

Pe multiplies the two marginals: humans pass 78 percent of items, the judge passes 75 percent, so two labelers guessing at those rates already agree on 64 percent of items by chance. Kappa credits the judge only with agreement above that floor.

The degenerate judge test

Replace the judge with a rubber stamp that passes everything. On this item set it agrees with humans on 78 of 100 items: raw agreement 78 percent, and it catches zero failures. Its kappa: Po = 0.78, Pe = (0.78 × 1.00) + (0.22 × 0.00) = 0.78, so kappa = (0.78 - 0.78) / (1 - 0.78) = 0.00. Exactly what it deserves. With a 78 percent pass base rate, raw agreement hands a useless judge a passing grade. Kappa does not.

Reporting discipline

Kappa never travels alone. Report it beside the matrix and the raw agreement: kappa compresses both error types into one number, and slide 9 shows the two errors have wildly different prices. A capability can post a respectable kappa while its false passes, the expensive error, stay too high to gate on.

Slide 09 · Error costs for gating

The two errors do not cost the same

ErrorWhat it means in the matrixWhat it costs when the capability gates
FALSE PASSHumans failed it, the judge passed it. 4 items in the example calibration.A bad answer ships. The judge was the last check before users, and it cleared, for the Support RAG app, a wrong refund window stated with a confident citation. User facing, unbounded, discovered by a customer.
FALSE ALARMHumans passed it, the judge failed it. 7 items in the example calibration.A human review, or a delayed good release. Bounded and priced in minutes: one reviewer reads one output. Annoying at scale, never a defect in production.

Consequence: bias the judge toward failing

  • Require a quoted evidence span for every claim the judge marks supported. No span, no pass.
  • Any unsupported claim fails the item. Not a deduction, not a partial credit: a fail.
  • Borderline resolves to fail. A false alarm costs a review. A false pass costs a user. Spend the cheap error.

The headline number changes

Report the false pass rate as the headline calibration number, with agreement and kappa as supporting statistics. The gate exists to stop bad releases, so the statistic that prices a bad release slipping through leads the report. In the example calibration that number is 4 / 22 = 18.2%, and it is why faithfulness does not gate yet at slide 11's first pass.

Slide 11 · The fix loop · judge prompt v3 to v4

Fix, rerun the same items, re-measure

rubric diff · the completeness criterion
# rubric_v3, the criterion behind 4 of 11 disagreements - FAIL if the answer omits important information. # rubric_v4: name the checkable condition + FAIL if the answer states a refund window + without the plan tier it applies to, or omits + the annual plan exception when the query + asks about refunds generally. # "important" was doing all the work, # and every reader defined it differently

The loop, stated as a rule

Revise the rubric or the judge prompt, move the version, rerun on the same validation items, and report the delta. Never tune and then report on a claim the loop has not re-measured: every trust number cites the rubric version, judge prompt version, and item set it was measured on. An unversioned improvement is an anecdote.

SLIDE 12 / 22PACE 11:50
Slide 13 · Abstention and coverage · example calibration numbers

A judge that cannot say "I cannot tell" guesses on schedule

The verdict set is pass, fail, abstain

  • Evidence missing: the criterion needs retrieved context the item does not contain. The judge cannot verify what it cannot see.
  • Criteria conflict: an answer is faithful to the context and violates the format instruction on the same claim, and the rubric gives no precedence.
  • Uncovered claims: claim decomposition produces a claim type the rubric does not address.

Every abstention routes to human review. An abstention is never silently counted as a pass, and never dropped from the denominator without being reported.

Coverage, reported beside agreement

the honest pairExample calibration, faithfulness: 200 items, judge abstains on 14. Coverage = 186 / 200 = 93%, agreement computed on the 186 decided items. The reportable unit is the pair: agreement on decided items, and the abstain rate.
the trapA judge abstaining on 40 percent of items can post 95 percent agreement on the easy 60 percent it chose to decide. That is not accuracy. It is a coverage problem disguised as accuracy.
the ruleAbstain rate sits beside agreement in every report, calibration_report.json included, slide 19. A rising abstain rate at constant agreement is a judge quietly shrinking its job.
SLIDE 13 / 22PACE 12:55
Slide 14 · Validating pairwise mode · example calibration

Pairwise is a different instrument. Validate it separately.

The protocol

  1. Swap consistency first. Rerun every pair with the order swapped, the Chapter 5 check. A pair the judge answers inconsistently across the swap is position noise, and agreement is not computed until that rate is measured and reported.
  2. Same pairs, both judges. Humans and the judge choose on identical pairs: A better, B better, or tie.
  3. Ties are explicit. A tie is a choice, counted in the comparison. Ties are never discarded and never split into half agreements to make the number prettier.

Example calibration, 120 pairs

choice agreement89 / 120 = 74.2% exact choice matches between judge and humans, ties included as choices.
tiesHumans called 18 ties, the judge called 11, and 7 tie calls matched. The judge under-calls ties: it manufactures preferences on pairs humans judge equal.
swap checkJudge choice flipped with position on 9 of 120 pairs (7.5%). Reported beside agreement, and those pairs are the first candidates for the human review route.
the scope rulePointwise calibration certifies pointwise judging only. A judge validated on slide 7 and then used for pairwise model selection is an uncalibrated instrument carrying a certificate for a different test.

Slide 15 · Judge drift

Trust expires. The validation set is frozen so you notice.

judge_golden_v1, and when it reruns

  • The set is frozen and versioned like the golden dataset from Chapter 3: items and human labels fixed, changes only as a new version.
  • On every judge model change, including the silent provider side kind. You detect those by rerunning, not by reading changelogs.
  • On every judge prompt or rubric change. A rubric edit is a new instrument; slide 11's loop is the small version of this rule.
  • Monthly, even if nothing changed. Candidate output distributions drift on their own, and the judge was calibrated on the old distribution.

The revocation rule is automatic

Calibration records a band, not just a point: faithfulness agreement 89 percent with a band of plus or minus 5 points at n = 200, from slide 4's arithmetic. A scheduled rerun landing outside the recorded band revokes GATE trust automatically for that capability, until a recalibration re-earns it. No meeting, no exception path, no grace period. Warn only is the state trust decays into, and the runner enforces it from the report's expiry and band fields, slide 19.

The mechanism of the inflation

Every rubric fix in the fix loop was motivated by specific disagreements on specific items. Report agreement on those same items and the number stops measuring judge quality on new outputs. It measures how well the fixes memorized the items that inspired them. Nothing looks wrong while it happens. The matrix just gets kinder, one motivated edit at a time.

The contamination rule

If a held-out item is ever used to fix a rubric, that item moves to the dev slice permanently, and the held-out slice is rebuilt from freshly labeled items before the next trust decision. There is no unseeing an item. This is Chapter 3's contamination rule, applied to the judge's dataset instead of the candidate's.

Why cross family, and what it buys

Agreement between two judges from different model families is real evidence, because their errors are less correlated. Same family judges, even at different sizes, share training data and failure modes: their agreement is weak evidence wearing a second badge. What the ensemble buys is a smaller, better targeted human review queue, the disagreements, which calibration already identified as the informative items.

The honest price

tokensChapter 5 costed one full judge pass at roughly 1.04M tokens. A two judge ensemble costs roughly 2.08M, before retries.
human loadEvery inter judge disagreement becomes a review task. That queue is the real operating cost, and it is priced in reviewer hours, not tokens.
the verdictAn ensemble is a routing tool, not an accuracy spell. It decides where humans look. It does not make either judge right.

Slide 18 · Production audit sampling · example audit series

Calibration ends. Auditing does not.

Weekly judge versus human agreement, production sample

Example audit series: 88, 89, 90, 87, 88, 85, 83, 81 across eight weeks. Week 7 prints below the band's lower edge, two weeks before any monthly recalibration would have looked.

The protocol

  • Random 2 percent sample of judged production cases, audited by humans weekly, lightly stratified by capability so no capability goes unobserved.
  • Same comparison as calibration: human verdict versus judge verdict on identical items, agreement computed the same way.
  • Plotted against the calibration band from slide 15, not against a fresh opinion each week.

What the audit catches early

Three drifts, one chart: the candidate changing its output distribution, the judge changing under a provider update, and production traffic drifting away from what the golden set covers. Formal recalibration is monthly at best. The audit is the early warning system between recalibrations.

Slide 20 · When calibration fails

A failed calibration is a result, not an embarrassment

1 · Narrow the judge scope
Judge claims support only, not overall quality. A smaller claim is a more checkable claim, and agreement rises because the task shrank.
2 · Warn only mode
Scores print in the report for that capability. They never reach the gate.
3 · Human review queue
The judge flags, humans decide, and the audit sampling rate for that capability goes up.
4 · Deterministic only gating
The release gate runs on Layers 1 and 2 for that capability until a future calibration passes.

What never happens

  • Never average the failure away. A failing capability folded into an overall judge score is a gate decision made by arithmetic nobody reviewed.
  • Never lower the threshold until it passes. That converts calibration into a search for a number the judge can already hit.
  • Never relabel humans into agreement. The labels are the standard. Editing the standard to match the instrument ends the measurement and keeps the costume.

Each rung of the ladder is a legitimate operating state with a name, an owner, and a path back up: recalibrate. Teams that predefine the ladder report failures. Teams that do not, hide them.

The architecture enforces the calibration

Only trusted scores can block. The runner reads the trust table before scoring, and an expired or missing calibration report drops the judge to warn only mode by default. Trust is not a comment in a wiki page. It is a config file the pipeline obeys.

Changing trust is a reviewed act

The trust table changes only through a recalibration run, and the diff lands in version control next to the report that justifies it. Anyone can read which numbers, on which items, under which rubric version earned each capability its GATE. That audit trail is what makes the Chapter 8 gate defensible.

Slide 22 · Key takeaways

Trust, measured

  1. Calibrate per capability against blind human labels on identical items. A judge trusted in general is trusted nowhere in particular.
  2. Report the matrix, kappa, and false passes, not a vibe. Raw agreement flatters at high base rates; the false pass rate is the number the gate pays for.
  3. Humans set the ceiling, disagreements set the worklist. Measure human versus human agreement first, then bucket every disagreement and fix what owns it.
  4. Trust expires. Freeze a judge validation set, rerun it on every judge change and monthly, and let an out of band result revoke the gate automatically.
