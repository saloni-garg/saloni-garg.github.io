One bug, five codebases: uniform-reward GRPO groups

In GRPO training, when every response in a group earns the same reward, the advantage should be exactly zero. Float32 group statistics invented a nonzero one instead. I found the bug class, fixed it, and sent the same fix upstream five times:

  • Ready

    verl-project/verl

    "[algo] fix: give uniform reward groups exactly zero grpo advantage." Scalar and vectorized paths fixed; new tests cover uniform groups at several sizes.

    PR #8349

  • Ready

    THUDM/slime

    "fix(data): give uniform reward groups exactly zero advantage." Fix in the grouped-reward post-processing, with new grouped-reward tests.

    PR #2494

  • Ready

    OpenRLHF/OpenRLHF

    "fix(ppo): give uniform reward groups exactly zero advantage in group_norm." The most severe instance found: uniform groups were getting advantages up to about 0.98 instead of 0.

    PR #1383

  • Ready

    NovaSky-AI/SkyRL

    "[fix][train] Give uniform reward groups exactly zero GRPO advantage." Fix in the PPO utilities, with new unit tests for uniform groups.

    PR #2531

  • Ready

    hiyouga/EasyR1

    "[algo] fix grpo giving uniform reward groups nonzero advantages." EasyR1 vendors the same algorithm code, bug included; fixed with tests.

    PR #11020

Compilers, TPU, and Triton

  • Ready

    google-pytorch/torch_tpu

    "Fix view decomposition returning a base larger than the view storage." The view decomposition fallback could build a base tensor larger than the storage it views; the fix re-checks the base and declines the decomposition.

    PR #5846

  • Ready

    google-pytorch/torch_tpu

    "Fix view decomposition IndexError on 0-d views with a storage offset." Zero-dimensional views with a storage offset crashed the decomposition; the fix declines it cleanly instead.

    PR #5847

  • Ready

    triton-lang/triton

    "[Interpreter] Fix NaN/Inf handling in interpreter float conversions." The Triton interpreter's float conversions mishandled NaN and infinity; fixed with regression tests.

    PR #12489

Verifiers and evaluation tooling

  • Ready

    openenv/OpenEnv

    "fix: stop awm code verifiers from passing on an untouched database." Over a thousand AWM code verifiers passed against a freshly seeded database; the fix adds a no-change guard. Test suite passing.

    PR #1477

OpenAI and Anthropic

  • Ready

    openai/human-eval

    "Fix completions ending in a decorator replacing the test's check()." In the execution harness, a completion ending in a bare decorator could replace the test's own check function and pass without running; the fix isolates the test block.

    PR #72

  • Ready

    anthropics/jacobian-lens

    "Raise in JacobianLens.save() when the storage dtype would turn finite entries into inf." Saving cast Jacobians to fp16 unchecked, silently turning large finite entries into infinity; the fix raises a clear error naming the layer.

    PR #21

Also open: a listing PR adding memfix to punkpeye/awesome-mcp-servers (PR #16020).
