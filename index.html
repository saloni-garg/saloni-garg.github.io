One bug, five codebases: uniform-reward GRPO groups

In GRPO training, when every response in a group earns the same reward, the advantage should be exactly zero. Float32 group statistics invented a nonzero one instead. I found the bug class, fixed it, and sent the same fix upstream five times:

  • verl-project/verl

    "[algo] fix: give uniform reward groups exactly zero grpo advantage."

    Scalar and vectorized paths fixed; new tests cover uniform groups at several sizes.

    PR #8349

  • THUDM/slime

    "fix(data): give uniform reward groups exactly zero advantage."

    Fix in the grouped-reward post-processing, with new grouped-reward tests.

    PR #2494

  • OpenRLHF/OpenRLHF

    "fix(ppo): give uniform reward groups exactly zero advantage in group_norm."

    The most severe instance found: uniform groups were getting advantages up to about 0.98 instead of 0.

    PR #1383

  • NovaSky-AI/SkyRL

    "[fix][train] Give uniform reward groups exactly zero GRPO advantage."

    Fix in the PPO utilities, with new unit tests for uniform groups.

    PR #2531

  • hiyouga/EasyR1

    "[algo] fix grpo giving uniform reward groups nonzero advantages."

    EasyR1 vendors the same algorithm code, bug included; fixed with tests.

    PR #11020

RLHF reward correctness

  • allenai/open-instruct

    "Fix R1-style format reward gate for non-default reward scales."

    The format reward gate compared scores against a literal 1 instead of the configured reward scale, so non-default scales were gated wrong; the fix compares against the configured scale, with tests.

    PR #2134

  • allenai/open-instruct

    "Fix: Key local dataset directory caches on directory content, not path."

    Dataset caches for a local directory of shards were keyed on the directory path alone, so rewriting the shards in place silently trained on stale rows; the fix keys the cache on a hash of the directory contents, with tests.

    PR #2159

  • NovaSky-AI/SkyRL

    "[fix][arctic_rl] detect limit at the top level only when capping bird reward queries."

    The arctic_rl BIRD reward skipped its 5000-row cap whenever the text LIMIT appeared anywhere in a query, including inside a subquery or a comment; the fix counts only a top level LIMIT clause, with tests.

    PR #2603

Compilers, TPU, and Triton

  • google-pytorch/torch_tpu

    "Fix view decomposition returning a base larger than the view storage."

    The view decomposition fallback could build a base tensor larger than the storage it views; the fix re-checks the base and declines the decomposition. Landed on main via Copybara, 30 October 2026.

    PR #5846 - landed

  • google-pytorch/torch_tpu

    "Fix view decomposition IndexError on 0-d views with a storage offset."

    Zero-dimensional views with a storage offset crashed the decomposition; the fix declines it cleanly instead. Landed on main via Copybara, 29 October 2026.

    PR #5847 - landed

  • triton-lang/triton

    "[Interpreter] Fix NaN/Inf handling in interpreter float conversions."

    The Triton interpreter's float conversions mishandled NaN and infinity; fixed with regression tests. Merged 30 October 2026.

    PR #12489 - merged

Verifiers and evaluation tooling

  • openenv/OpenEnv

    "fix: stop awm code verifiers from passing on an untouched database."

    Over a thousand AWM code verifiers passed against a freshly seeded database; the fix adds a no-change guard. Test suite passing.

    PR #1477

  • openai/human-eval

    "Fix completions ending in a decorator replacing the test's check()."

    In the execution harness, a completion ending in a bare decorator could replace the test's own check function and pass without running; the fix isolates the test block.

    PR #72

  • anthropics/jacobian-lens

    "Raise in JacobianLens.save() when the storage dtype would turn finite entries into inf."

    Saving cast Jacobians to fp16 unchecked, silently turning large finite entries into infinity; the fix raises a clear error naming the layer.

    PR #21

Inference serving

  • ai-dynamo/dynamo

    "fix(profiler): recognize SGLang --tp-size/--pp-size spellings in multinode placement."

    The profiler sized SGLang workers launched with the short size spellings as single-GPU instances and stripped their multinode placement; the fix teaches the parser those spellings, with the first unit tests for set_multinode_config.

    PR #17502

  • ai-dynamo/dynamo

    "fix(operator): reject backendFramework resolution failures at admission."

    Admission validation for disaggregated serving configs now resolves each component's backend framework the way the renderer does and rejects what it cannot resolve, including mixed worker frameworks across a graph, with tests.

    PR #17801

  • sgl-project/sglang

    "[Feat] metrics: expose detokenizer worker processing time."

    Adds a processing time histogram for the detokenizer worker (sglang:detokenizer_processing_seconds), one slice of the metric coverage umbrella in issue #43304, with tests.

    PR #47877

  • NVIDIA/Model-Optimizer

    "fix static nvfp4 fake quant for unpromoted weight quantizers in TensorQuantizer."

    Static NVFP4 fake quantization in TensorQuantizer raised NotImplementedError for weight quantizers; the fix routes it through the static blockwise fake quant path, with tests.

    PR #3167
